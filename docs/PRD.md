# PRD：信息概览页面（v1.2.0）

> 版本：v1.2.0 迭代 · 产品：dsh-bottom-info-bar（底部信息栏插件）
> 关联文档：`docs/product-definition.md`（产品定义）、`docs/TECH-DESIGN.md`（技术设计）

## 背景与目标
底部信息栏插件已有"一行式"花费/余额展示。用户需要一个**完整的用量追踪页面**，像主流 AI 产品那样，一页看清：
- 花了多少钱（今日/本月/近30天/累计）
- 每一笔使用记录（时间、模型、服务商、token、费用）
- 各模型用量排名（谁最费钱、谁最费 token）
- 花费趋势（近 7/30 天）

页面有**两个入口**：设置页导航 + 对话页顶部标签栏，进入的是**同一个页面**。

## 目标用户
非技术个人开发者（用户本人）。页面语言：简体中文，措辞与信息栏一致。

## 功能需求

### FR-1 双入口：设置页 + 对话页顶部标签栏
- 描述：在 DSH 设置页的左侧导航中加入「信息概览」页面项；同时在对话页顶部的视图标签栏加入「信息概览」标签。两者渲染同一个页面组件、同一份数据。
- 验收标准：
  - Given 用户打开设置，When 查看左侧导航，Then 存在名为「信息概览」的入口，点击后右侧显示信息概览页面。
  - Given 用户在任意对话中，When 查看对话顶部标签栏，Then 存在名为「信息概览」的标签，点击后对话区切换为信息概览页面。
  - 两个入口显示的内容一致（同一组件、同一数据源）。
  - 标签栏原有标签（对话/轨迹等）不受影响，可正常来回切换。

### FR-2 花费总览卡
- 描述：页面顶部展示四个金额：今日花费、本月花费、近30天花费、累计花费。口径与信息栏一致（北京时间、活动币种）。
- 验收标准：
  - Given 存在历史记账数据，When 打开信息概览页面，Then 四个金额卡均显示正确金额（与信息栏"今天/近一月/全部"一致；本月为新指标）。
  - 金额格式：币种符号 + 千分位 + 2 位小数（如 ¥1,234.56 / $15.50）；金额大于 0 但小于 0.01 时显示「＜¥0.01」防误导；无数据时显示 ¥0.00。
  - 页面停留时数据每 30 秒自动刷新。

### FR-3 使用记录明细列表
- 描述：展示每笔 LLM 调用的记录：时间、模型、服务商、输入/缓存/输出 token、该笔费用。最新在前，默认显示最近 20 条，可"加载更多"（每批 20 条，直至全部）。
- 验收标准：
  - Given 有 N 条记账记录，When 打开页面，Then 按时间倒序显示最近 20 条，每条含：时间（本地时区 MM-DD HH:mm）、模型显示名、服务商显示名、输入 token、缓存读取 token、缓存写入 token、输出 token、费用。
  - 点击"加载更多"后追加下一批 20 条，直至无更多（按钮消失或置灰）。
  - 记录内容与 `usage-records.json` 一致（逐条对应）。
  - 费用计算与信息栏"本对话花费"同一算法（peak-valley 按记录时刻的时段计费）。
  - 记录仅展示（只读），无删除/编辑入口。
  - 列表为空时显示"暂无使用记录"空态提示。

### FR-4 各模型用量统计
- 描述：按模型汇总全部记录：调用次数、输入/缓存/输出 token、费用；按费用降序排列，展示占比。
- 验收标准：
  - Given 存在多模型记录，When 打开页面，Then 每个模型一行：模型名、调用次数、总 token、总费用（含币种），按费用从高到低排列。
  - 费用占比以条形展示（纯 CSS），便于直观比较。
  - 模型名与服务商名使用与信息栏一致的显示名（DSH 目录名 → 回退原始 id）。

### FR-5 花费趋势图（近 7/30 天）
- 描述：每日花费柱状图，可切换 7 天 / 30 天；显示当日金额与高峰/空闲价对比（复用现有数据）。
- 验收标准：
  - Given 存在历史数据，When 打开页面，Then 显示按日柱状图（每日一个柱子，高度按花费比例）。
  - 提供 7 天 / 30 天切换按钮，切换后图表与标题更新。
  - hover/悬停柱子显示该日金额（title 提示即可）。
  - 无数据日期显示空柱或 0，不报错。

### FR-6 数据来源与一致性
- 描述：页面所有数据来自插件 host 端 RPC（本地 HTTP，零外部依赖），与信息栏同一数据源、同一计算口径。
- 验收标准：
  - 页面通过现有 `/_dsh/dsh-bottom-info-bar/<method>` RPC 获取数据；新增 RPC 遵循现有路由/同源防护约定。
  - 页面打开到数据可见 ≤ 1 秒（本地调用）。
  - 信息栏显示的"今天/近一月/全部"与页面总览卡一致（同一函数）。
  - host 端不因页面新增任何写盘逻辑（记录已存在；只新增读取/聚合）。

## 非功能需求
- **安全**：零新增密钥/敏感数据落盘；RPC 仅本机同源可访问（沿用现有 sameOrigin 防护）；页面不注入脚本、不执行用户输入。
- **性能**：明细加载 20 条/批；聚合统计在 host 端内存计算（≤3000 条记录，纳秒级）；页面 30s 轮询与信息栏共用节奏，不新增高频请求。
- **兼容性**：旧版 `usage-records.json`（无新字段）直接兼容；低版本 DSH 若标签栏 slot 不存在则设置页入口照常工作（注册失败静默，不影响信息栏本体）。
- **可维护性**：新增纯函数放 host.js 可单测区块；client 页面组件复用现有 rpc()/样式工具。

## 非目标（v1.2.0 不做）
- 不做导出 CSV / 下载账单。
- 不做多币种并行展示、汇率换算。
- 不做预算设置、超支提醒配置项（沿用信息栏余额预警）。
- 不做订阅额度管理（由独立插件负责）。
- 不做云端同步、多设备共享。
- 不提供记录删除/编辑/归档。

## 成功指标
- 两个入口均可打开同一页面，四个数据模块全部渲染真实数据。
- 总览卡与信息栏数字一致；明细与 JSON 文件一致。
- 全量测试（含新增用例）通过；CI 绿。
- 用户确认页面布局与信息符合预期。
