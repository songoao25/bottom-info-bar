# 底部信息栏 UI 语义与浮窗规范

日期：2026-08-22
状态：已评审，按小功能分批实现

## 适用原则

本插件运行在 DSH Web 界面，不是原生 Apple App，因此不声称“符合 Apple HIG”。本规范采用 DeepSeek Harness `apple-dev-norms` 所允许迁移的原则：清晰、克制、一致、语义化颜色、颜色不是唯一状态信号，以及深浅主题和高对比度可用。

浮窗只解释鼠标所指的标签；常规内容保持短小。已确认继续使用原生 `title`，不新增自定义 Hover Card；文案需优先给出当前状态和唯一下一步操作。

## 文字层级

| 层级 | 规则 | 当前/目标用途 |
| --- | --- | --- |
| 主标签 | `label-primary`，600 | 服务商名；明确的状态名 |
| 关键数值 | 主文字，700，等宽数字 | 余额、花费、百分比、倒计时 |
| 普通信息 | `label-tertiary`，常规字重 | 模型名、单位、说明文字 |
| 降级说明 | `label-tertiary`，常规字重 | `（估算）`、更新时间 |
| 不使用加粗 | 不用字重制造“异常” | 错误和警告依靠语义色、文字和图标共同表达 |

加粗只表达信息层级，不能兼作颜色或严重程度的替代品。

## 标签与浮窗内容

| 标签 | 行内显示 | 浮窗内容 | 状态要求 |
| --- | --- | --- | --- |
| 服务商 / 模型 | 服务商加粗，模型常规；视觉模型额外显示能力胶囊 | 服务商、模型、计费模式、能力（如“支持图像输入”）、插件版本 | 不显示凭据、内部 ID 或模型名称猜测结果 |
| 视觉能力胶囊 | `视觉`，椭圆底色 | `支持图像输入` | 胶囊文字本身是颜色之外的识别方式 |
| 余额 | `余额 ¥x.xxx`，数值加粗 | 实际/估算来源、余额、更新时间、低余额阈值（若触发） | 余额充足时不用绿色；低余额仅将数值加粗为鲜红色 |
| 峰谷定价 | `高峰价` / `空闲价` | 输入、缓存、输出单价；高峰时段；统一说明为北京时间 | 价格状态不是错误，不能使用红色 |
| 价格倒计时 | `距高峰 00:00` 或 `距空闲 00:00`，仅数字加粗 | 下一次切换的完整日期和时间（北京时间） | 默认中性文字 |
| 本对话花费 | `本对话 ¥x.xxx`，数值加粗 | 今天、近一月、全部；币种口径 | 无法统计时说清范围，不用成功色 |
| 订阅额度 | `5h 72%` 等，百分比加粗 | 订阅源、套餐、每个窗口的剩余/已用、重置时刻 | 正常额度中性；低额度仅将对应百分比加粗为鲜红色 |
| 订阅倒计时 | `距重置 1d 2h`，数字加粗 | 对应窗口、剩余/已用、重置时刻 | 必须和行内显示的同一窗口对应 |
| 刷新失败 | `刷新失败` | 原因、保留的是哪次成功快照、下一次自动重试的含义 | 鲜红色文字；不能伪装成最新实时数据 |
| 配置或认证错误 | 简短错误标签 | 原因与唯一下一步操作 | 错误色；不可显示 token、路径或原始服务端响应 |
| 有新版本 | `新版本提醒` | 可更新的版本和用户下一步操作 | 信息/行动色；没有点击操作时不能用下划线伪装链接 |

## 颜色语义

仅使用 DSH 已提供的语义主题变量；需要新增的“视觉能力”变量必须提供浅色、深色和更高对比度变体，不能把固定 HEX 当作唯一实现。

| 语义 | 行内表现 | 现有问题 | 目标规则 |
| --- | --- | --- | --- |
| 默认信息 | 主/三级文字 | 无 | 作为绝大多数常态数据的默认色 |
| 高峰价 | 主文字 + `高峰价` 文字 | 琥珀色小字号可读性不足 | 用清晰文字表达价格状态；无 `⚠`，不表示故障 |
| 空闲价 | 绿色 + `空闲价` 文字 | 无 | 表达明确的优惠状态；不复用到“正常额度” |
| 低余额、低订阅额度、刷新失败 | 鲜红色 + 明确文字 | 正常订阅额度也用绿色，含义过多 | 统一为需要处理的警示；低额度阈值为剩余 ≤20% |
| 配置缺失、认证失败、无有效数据 | 鲜红色 + 明确错误文字 | 图标与颜色混用造成噪声 | 仅表示需要处理的阻断性错误 |
| 新版本可用 | 鲜红色 + `新版本提醒`文字 | 下划线像链接 | 提醒用户处理；没有实际链接就不加下划线 |
| 视觉能力 | 独立紫色系胶囊 + `视觉` 文本 | 尚未实现 | 只表示能力，不表示状态、警告或可点击性 |

### 视觉模型：紫色优于克莱因蓝

在“脑紫色”和克莱因蓝之间，选择**低饱和紫色系**，但不使用“脑”图标；使用文字 `视觉` 或图像能力图形。

- 克莱因蓝饱和度过高，且蓝色在桌面界面中通常被理解为可点击的行动色；用于非交互能力标签会产生错误暗示。
- 紫色不与红/琥珀/绿三种状态语义冲突，适合表达稳定、非紧急的“模型能力”。
- 胶囊必须同时保留文字，背景仅作辅助；前景与背景在浅色、深色和提高对比度下均须验证。若主题不能提供合格的语义变量，则宁可暂不着色，也不写死单一紫色。

## 视觉模型识别边界

当前插件从 `llm.listModels(provider)` 只保存模型的 `id` 与 `name`。因此它**尚未拥有可判定图像输入能力的数据**，也不能通过模型 ID、显示名或供应商名进行推测。

实现前需完成以下探针：

1. 在当前 DSH 版本中确认模型目录返回的能力字段及稳定含义。
2. 只接受明确的“支持图像输入”能力标记，未知或缺失时不显示胶囊。
3. 将能力元数据和名称缓存分开；模型/服务商切换时一并刷新。
4. 为“明确支持 / 明确不支持 / 字段缺失 / 目录读取失败”各写一条测试，保证不出现误标。

## 分批开发与提交

1. `docs`：本规范与现有标签审计（本提交）。
2. `refactor`：集中定义语义样式类，迁移现有标签；不改变数据与布局。
3. `fix`：保持原生 `title`，精简并统一每类标签的浮窗文案。
4. `feat`：接入 DSH 已验证的图像输入能力字段，显示低饱和紫色 `视觉` 胶囊。
5. `fix`：迁移状态色——正常额度中性、新版本为行动色、错误/警告分级清晰。

每一步均在独立分支或独立提交完成，执行构建、全量测试、`git diff --check` 和浅色/深色人工界面验收后再合并；不直接改写 `main`。

## 依据

- Apple HIG 的 Color：颜色应保持语义一致、适配深浅主题和高对比度，且不能是唯一的信息载体。
- Apple HIG 的 Accessibility：小字号文字的对比度至少按 WCAG AA 4.5:1 验证；粗体大字号可按 3:1 验证。
- Apple HIG 的 Offering help：浮窗只解释被指向的单个控件，保持简短；复杂说明应改进界面或使用更合适的帮助形式。
- DeepSeek Harness `apple-dev-norms`：本 Web 插件只迁移上述通用原则，不宣称为原生 Apple HIG 实现。
