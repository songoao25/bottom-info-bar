# 底部信息栏 UI 语义与浮窗规范

日期：2026-08-22
状态：已实施；随功能变更持续复核

## 适用原则

本插件运行在 DSH Web 界面，不是原生 Apple App，因此不声称“符合 Apple HIG”。本规范采用 DeepSeek Harness `apple-dev-norms` 所允许迁移的原则：清晰、克制、一致、语义化颜色、颜色不是唯一状态信号，以及深浅主题和高对比度可用。

浮窗只解释鼠标所指的标签；常规内容保持短小。已确认继续使用原生 `title`，不新增自定义 Hover Card；文案需优先给出当前状态和唯一下一步操作。

## 文字层级

| 层级 | 规则 | 当前/目标用途 |
| --- | --- | --- |
| 主标签 | `label-primary`，600 | 服务商名；明确的状态名（高峰价、空闲价、错误、更新） |
| 关键数值 | 主文字，700，等宽数字 | 余额、花费、百分比、倒计时 |
| 普通信息 | 高对比辅助文字，常规字重 | 模型名、说明文字；数据令牌以外的单位 |
| 降级说明 | 高对比辅助文字，常规字重 | `（估算）`、更新时间 |
| 不使用加粗 | 不用字重制造“异常” | 错误和警告依靠语义色与明确文字共同表达；不使用装饰性图标 |

加粗只表达信息层级，不能兼作颜色或严重程度的替代品。

数值统一采用“**标签在前 → 加粗数据令牌**”的语法：`LLM 1.2s`、`输入 12K tok`、`缓存命中 48%`、`距重置 3h 12m`。数字与紧随的西文单位、百分号或货币符号作为一个整体加粗；中文界面中数字与中文量词遵循混排留白：`余额 ¥3.00`、`本对话 $0.012`、`3 轮`、`12 步`、`5 小时`。标签保持常规字重；标签与数据不用普通字符空格拼接，而是由统一的 4px 布局边界分隔。外部信息组再用分隔符两侧各 6px 的留白分组。

## 间距与分组

信息栏使用两级节奏：外部信息组之间以 `|` 分隔，分隔符两侧各 6px；同一信息组内部使用更紧的固定间距（标签与数据为 4px，数值后的 `低` 为 3px，服务商/模型圆点两侧为 4px）。因此阅读顺序清晰：先识别一组完整信息，再跳到下一组；不会因为中英文混排或 12px 小字号的字宽差而忽松忽紧。

## 标签与浮窗内容

| 标签 | 行内显示 | 浮窗内容 | 状态要求 |
| --- | --- | --- | --- |
| 服务商 / 模型 | 始终为“服务商 · 模型”；服务商加粗，模型常规；视觉模型额外显示能力胶囊 | 服务商、完整模型名、计费模式、能力（如“支持图像输入”）、插件版本 | 模型名如以服务商开头，只在模型部分移除重复前缀；不显示凭据、内部 ID 或模型名称猜测结果 |
| 视觉能力胶囊 | `视觉`，椭圆底色 | `支持图像输入` | 胶囊文字本身是颜色之外的识别方式 |
| 余额 | `余额 ¥x.xxx 低`，数值加粗 | 实际/估算来源、余额、更新时间、低余额阈值（若触发） | 余额充足时不用绿色；低余额使用鲜红色数字与无框 `低` 字 |
| 峰谷定价 | `高峰价` / `空闲价` | 输入、缓存、输出单价；高峰时段；统一说明为北京时间 | 高峰价使用警示红表示成本较高；空闲价使用绿色表示更优惠；两者均有文字 |
| 价格倒计时 | `距高峰 00:00` 或 `距空闲 00:00`，仅数字加粗 | 下一次切换的完整日期和时间（北京时间） | 默认中性文字 |
| 本对话花费 | `本对话 ¥x.xxx`，数值加粗 | 今天、近一月、全部；币种口径 | 无法统计时说清范围，不用成功色 |
| 订阅额度 | `5h 72% 低` 等，百分比加粗 | 订阅源、套餐、每个窗口的剩余/已用、重置时刻 | 正常额度中性；低额度使用鲜红色百分比与无框 `低` 字 |
| 订阅倒计时 | `距重置 1d 2h`，数字加粗 | 对应窗口、剩余/已用、重置时刻 | 必须和行内显示的同一窗口对应 |
| 刷新失败 | `刷新失败` | 原因、保留的是哪次成功快照、下一次自动重试的含义 | 鲜红色文字；不能伪装成最新实时数据 |
| 配置或认证错误 | 简短错误标签 | 原因与唯一下一步操作 | 错误色；不可显示 token、路径或原始服务端响应 |
| 有新版本 | `新版本提醒` | 可更新的版本和用户下一步操作 | 按产品决定使用鲜红色提醒；没有点击操作时不能用下划线伪装链接 |

## 颜色语义

文字默认使用 DSH 的主题变量。视觉能力胶囊使用用户指定的电光蓝 `#0057FF`（白字、深蓝细边）；警示与空闲价在 DSH 实际深浅主题属性下使用各自的语义色，并在系统启用“增强对比度”时切换至更高对比度色阶。颜色始终配合文字，不作为唯一状态信号。

| 语义 | 行内表现 | 现有问题 | 目标规则 |
| --- | --- | --- | --- |
| 默认信息 | 主/三级文字 | 无 | 作为绝大多数常态数据的默认色 |
| 高峰价 | 警示红 + `高峰价` 文字 | 无 | 表达成本较高，不与“故障”混淆；无 `⚠` |
| 空闲价 | 绿色 + `空闲价` 文字 | 无 | 表达明确的优惠状态；不复用到“正常额度” |
| 低余额、低订阅额度、刷新失败 | 鲜红色 + 明确文字 | 无 | 统一为需要处理的警示；低余额、低额度附无框 `低` 字，低额度阈值为剩余 ≤20% |
| 配置缺失、认证失败、无有效数据 | 鲜红色 + 明确错误文字 | 图标与颜色混用造成噪声 | 仅表示需要处理的阻断性错误 |
| 新版本可用 | 鲜红色 + `新版本提醒`文字 | 下划线像链接 | 提醒用户处理；没有实际链接就不加下划线 |
| 视觉能力 | 电光蓝胶囊 + 模型全名与 `视觉` 文本 | 已实现 | 只表示能力，不表示状态、警告或可点击性 |

### 视觉模型：固定电光蓝

视觉能力使用用户指定的电光蓝 `#0057FF`，不使用图标，使用文字 `视觉`。

- 蓝色只用于稳定的视觉能力，不参与价格、余额、额度或错误等状态语义，避免同色多义。
- 胶囊保留模型名和“视觉”文字，背景仅作辅助；白字与填充色的对比度为 5.52:1，人工验收覆盖浅色与深色外观。
- 该胶囊为纯展示内容，不可点击；不使用下划线或行动图标，避免被理解为链接。

`视觉` 是模型能力名称，使用电光蓝胶囊承载完整内容；`低` 是相邻数值的状态修饰，使用同警示红的无框文字。两者不强行共用形状：这保留了能力标签的稳定边界，也避免状态提示突然制造第二个视觉焦点。

## 服务商与模型展示契约

行内格式固定为 **服务商 · 模型**。前者回答“这次请求经过哪个 API/订阅服务”，后者回答“实际选择了哪个模型”；两者不能互相替代。模型显示名只在**以当前服务商完整名称开头**时移除这一个重复前缀，且不修改其他文字、大小写或版本号。这个规则既避免 `DeepSeek · DeepSeek-V4-Flash` 的重复，也保留聚合 API 下真正重要的模型厂商信息。

| 当前服务商 | 模型目录显示名 | 行内结果 | 说明 |
| --- | --- | --- | --- |
| DeepSeek | DeepSeek-V4-Flash | `DeepSeek · V4-Flash` | 去掉重复服务商前缀 |
| OpenAI | GPT-4o | `OpenAI · GPT-4o` | 服务商与模型天然不同 |
| Anthropic | Claude 3.5 Sonnet | `Anthropic · Claude 3.5 Sonnet` | 保留完整模型系列名 |
| Google | Gemini 2.5 Pro | `Google · Gemini 2.5 Pro` | Google 是 API 服务商，Gemini 是模型系列 |
| OpenRouter | Claude 3.5 Sonnet | `OpenRouter · Claude 3.5 Sonnet` | 关键：保留路由渠道与实际模型 |
| OpenRouter | OpenAI GPT-4o | `OpenRouter · OpenAI GPT-4o` | 不能因为模型内含其他厂商名而裁剪 |
| ChatGPT 订阅 | GPT-5 Codex | `ChatGPT · GPT-5 Codex` | 订阅制左侧表达订阅来源 |
| OpenCode Go | DeepSeek V4 Flash | `OpenCode Go · DeepSeek V4 Flash` | 左侧表达订阅来源，右侧完整保留模型厂商 |

模型与服务商完全相同（如 `Qwen · Qwen`）时保留两者，宁可略有重复，也不隐去“经由哪个 API”的关键信息。完整原始显示名始终可在悬浮提示中查看。

## 视觉模型识别边界

插件从 DSH 模型目录读取 `inputModalities`；只有其中明确包含 `image` 时，host 才下发 `acceptsImageInput: true`。客户端不根据模型 ID、显示名或服务商名称猜测能力；字段缺失、目录读取失败或明确不支持时均不显示胶囊。

能力元数据与显示名分开缓存，并随模型/服务商切换刷新。静态回归测试覆盖“仅接受 host 显式 true”的边界。

## 依据

- Apple HIG 的 Color：颜色应保持语义一致、适配深浅主题和高对比度，且不能是唯一的信息载体。
- Apple HIG 的 Accessibility：小字号文字的对比度至少按 WCAG AA 4.5:1 验证；粗体大字号可按 3:1 验证。
- Apple HIG 的 Offering help：浮窗只解释被指向的单个控件，保持简短；复杂说明应改进界面或使用更合适的帮助形式。
- DeepSeek Harness `apple-dev-norms`：本 Web 插件只迁移上述通用原则，不宣称为原生 Apple HIG 实现。
